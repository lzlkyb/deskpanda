## 1. 新发现(上午评估没有的)

### 1.1 🔴 auto_accept 前后端字段漂移 = 真功能 bug(当日已修,见 [Unreleased])

- 后端 store 有真值(`rc/service/trust.rs:153`)、setter 命令也在(`commands/rc.rs` 的
  `rc_device_auto_accept_set`),但 IPC 投影 `RcTargetDevice` **漏了这个字段**。
- 前端 4 处读 `target.auto_accept`(`RcDeviceManageActions.tsx:56,59` / `RcPageFiles.tsx:118` /
  `RcA2DeviceDetail.tsx:247`)→ 恒 `undefined`:开关永远显示「未开启」,
  `!undefined` 恒 true → **只能开、关不掉**。TS 编译器对「后端少字段」零感知。
- 修法:投影补字段 + 镜像契约守卫 `src/__tests__/RcTargetDeviceMirror.test.ts`(TS ⊆ Rust 逐字段钉)。

### 1.2 🔴 门禁静默失效:`.githooks/pre-push` 是 644 模式(当日已修,见 [Unreleased])

git 里存的非可执行 → clone 后配 `core.hooksPath`,钩子被 git **静默跳过**(仅一行 hint)。
当天 main 的 macOS 编译红灯能溜进去,根因即此(上个会话 push 时门禁根本没跑)。

### 1.3 🟠 `lib/utils.ts`:1343 行 / 99 个导出,其中 81 个死代码

全量普查(grep 全仓生产引用):history/knowledge/OCR/barcode/hotkey/recording 等 PastePanda
血统的导出**零引用**(连 `cn` 都只有测试在引用)。真正在用的 18 个:
`permissionErrorInfo, rcDeviceStatus, rcCheckTime, parseHistoryTime, formatPairCode,
pairCodeDigest, truncate, formatBytes, formatRate, errText, copyToClipboard, cursorCssFor,
rcDeviceKind, rcDeviceTypeLabel, remoteCodecLabel, copyText, formatBytesPerSec, isImeComposing`。
清理时保 18 删 81,拆成 `rc*` 主题文件(仓规:不往 utils.ts 堆)。

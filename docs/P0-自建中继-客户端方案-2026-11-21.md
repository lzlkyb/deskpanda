## 0. 问题回顾

- 打洞失败回落 n0 公共中继(use1 美东 / euw1 欧洲 / aps1 孟买),国内用户约等于不可用。
- 自建香港 BGP 中继后,客户端需要:①把自建中继排到列表最前;②带防滥用 token;
  ③n0 保留兜底(自建挂了不至于全断);④用户与验收都能看到「这个会话实际走的哪个中继」。

## 1. 现状(实查)

| 项 | 现状 | 位置 |
|---|---|---|
| 中继配置 | `Endpoint::builder(presets::N0)`,即 n0 生产表,无 token | `net/endpoint.rs:124` |
| 诊断快照 | 已有 `relay_latencies_ms`(探测延迟)+ `preferred_relay`(探测偏好) | `net/diagnostics.rs` → 前端 `rcNetDiag.ts` |
| 缺口 | ①没有「**当前实际连接**的中继」;②没有任何自建中继入口;③探测延迟只针对 net_report 时刻,会话中途切换看不到 | — |

## 2. iroh 1.1 API 盘点(本机 registry 源码实查,方案每一行都对着真实 API)

| API | 用途 |
|---|---|
| `RelayMode::Custom(RelayMap)` / `Builder::relay_mode()` | 自定义中继表的总入口;`presets::N0` 的其余能力(pkarr 寻址等)不受影响,只覆盖中继部分 |
| `RelayMap::try_from_iter([&str])` | 从 URL 字符串建表 |
| `RelayConfig::new(url, quic)` + **`RelayConfig::with_auth_token()`** | 🔴 **逐中继**配 token:自建带 token、n0 不带,可共存一张表(整表级 `RelayMap::with_auth_token` 会把 token 发给 n0,不用) |
| `RelayMap::extend(&other)` | 与 `iroh::defaults::prod::default_relay_map()`(n0 生产表)合并 → n0 自动兜底 |
| `RelayQuicConfig::new(port)` | 中继的 QAD(QUIC 地址发现,类 STUN)端口;**建议开**(7824),提升打洞质量 |
| `endpoint.home_relay_status() -> Watcher<Vec<RelayStatus>>` | **实时**每台中继的连接状态(url + state),「当前中继」的数据源,零成本 |

## 3. 设计决策(三处取舍)

### 决策 A · 配置注入方式

| 方案 | 说明 | 判断 |
|---|---|---|
| **A1(推荐)** | **编译期常量为默认 + 环境变量覆盖**:`DEFAULT_RELAY_URL` / `DEFAULT_RELAY_TOKEN` 常量进二进制;`DESKPANDA_RELAY_URL` / `DESKPANDA_RELAY_TOKEN` env 可覆盖(本地调试 / 灰度换端点) | 与 Gitee 镜像的教训完全同构(CHANGELOG 2026-11-20:装在用户机器上的应用读不到 env ⇒ 默认值必须编译期钉死);改动最小;不碰端点生命周期 |
| A2 | 设置页运行时可配 | 需要端点销毁重建的整套生命周期逻辑(`get_or_bind` 是进程级单例,「永不关闭」是模块头注释的红线);价值/成本比差,**后置**——等灰度真有切换需求再做 |
| A3 | 纯 env | 直接违背 Gitee 教训,否 |

### 决策 B · n0 兜底的去留(验证期)

| 方案 | 说明 | 判断 |
|---|---|---|
| **B1(推荐)** | 自建排最前 + n0 全表兜底(`RelayMap::extend` 合并) | 自建中继宕机/被墙时段不至于全断;iroh 按 home relay 选择机制会优先低延迟者(香港 BGP 对国内用户恒优于美欧);**验证期满后可一行删掉兜底** |
| B2 | 纯自建 | 验证期一旦自建抖动,用户直接退回「连不上」,风险不对称;否 |

### 决策 C · 「当前中继」的展示层级

| 方案 | 说明 | 判断 |
|---|---|---|
| **C1(推荐)** | 两层:**诊断卡片**(会话外)显示「当前中继:xxx(已连接/连接中)」;**会话横幅/状态**(会话中)在 `RcStatus` 增加 `home_relay` 字段,中继路径时显示中继域名 | 验收判据(交接文档 §6.5「中继路径判据」)需要会话级;排障需要诊断级;数据源同一个 Watcher |
| C2 | 只做诊断卡片 | 会话中实际走的哪个看不到,验收不了 §6.5;否 |

## 6. 风险与开放问题

| # | 风险/问题 | 口径 |
|---|---|---|
| 1 | shared_token 编译进二进制可被提取 | 它是**防滥用**不是访问控制(等同 CrossDesk 的连接密码模型);定向攻击者拿到 token 也只多用带宽,会话安全不在中继层(端到端 QUIC 加密 + 身份密钥)。文档写明,接受 |
| 2 | n0 兜底与自建共存时 iroh 的 home relay 选择 | iroh 按延迟择优;香港 BGP 对国内恒优。若出现「偶尔选了 n0」属预期行为(自建瞬时不可达),诊断卡片能看到——这正是要做它的原因 |
| 3 | relay 版本必须与客户端 iroh 同版本 | 被钉在 **iroh 1.1**(升级 iroh 需重基线 vendor,体检报告已立项);服务端部署时用 `n0computer/iroh-relay:1.1` 镜像或对应 tag |
| 4 | QAD 7824 端口 | 默认开;VPS 安全组记得放行 UDP 7824 |
